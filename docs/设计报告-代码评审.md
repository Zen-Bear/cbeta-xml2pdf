## 1. 项目概览

```
pycbeta/                     （约 1600 行 Python + 900KB paged.js + 默认 CSS）
  parser.py      P5 XML → IR（命名空间归一、校勘锚点回填、wit/resp 解析、缺字解析）
  model.py       IR 数据模型（Text/Lb/Pb/Gaiji/E/Note/NoteRef/App/AppRead/Work）
  names.py       canon/vol/work ID 规则
  gaiji.py       缺字库加载 + PUA
  render_html.py IR → 官方格式 HTML（cb_note 风格，分卷输出）
  render_pdf.py  IR → PDF-ready HTML → Chromium/Prince/WeasyPrint 可插拔
  render_docx.py IR → OOXML（真页底脚注、偈颂、缺字字体）
  theme.py       Theme：语义标签 → CSS/JSON → 多格式样式（含 pdf_docx.css）
  styles/cbeta_golden.css   HTML/EPUB 官方（golden）基底 CSS
  styles/pdf_docx.css       PDF/DOCX 默认主题（语义 type 钩子）
  assets/paged.polyfill.js  实验性页底脚注（不可靠，见风险）
  tests/         22 项 unittest
```

数据依赖：`cbeta/data/*.json`（缺字库）、`cbeta/fonts/`。

### 8.1 两个内置 CSS 文件

| 文件 | 定位 | 内容 |
|---|---|---|
| `pycbeta/styles/cbeta_golden.css` | HTML/EPUB 官方（golden）**基底** | `@font-face`、body 字体、`.head`/`.juan` 颜色、`div.lg` 表格、`p{text-indent:2em}` 等 |

### 8.2 各格式默认（不传 `--theme`）用哪个 CSS

| 格式 | cbeta_golden.css | pdf_docx.css | 原因 |
|---|---|---|---|
| HTML / EPUB | ✅（基底） | ❌ 不参与 | `HtmlRenderer.theme=None` 时保持 None，**不**自动加载主题 |
| PDF | ❌ | ✅ | `PdfRenderer` theme=None → `Theme()` 自动加载 pdf_docx.css |
| DOCX | ❌ | ✅（翻译成 OOXML） | `DocxRenderer` 同上；另有 默认值唯一定义处 `styles/pdf_docx.css` |
| MD | ❌ | ❌ | Markdown 无样式 |

### 8.3 修改指引

| 想改 | 方式 | 说明 |
|---|---|---|
| HTML/EPUB 观感 | 直接编辑 `styles/cbeta_golden.css` | 基底，改完即新官方；回退留 `.bak` 备份 |

### 8.4 `--theme` 语义（易踩坑，重点记）

`--theme` 是**替换**主题层（pdf_docx.css），不是叠加。因此：
- **HTML/EPUB**：主题层本来就不加载，`--theme xxx.css` = cbeta_golden.css 基底 + xxx.css 追加，微改直接生效，**不存在**"丢失主题"问题。
- **PDF/DOCX**：pdf_docx.css 被整个替换，主题文件需自带所需规则，否则样式与默认不同。

> 反例（勿用）：`--theme cbeta_golden.css` 不是"干净的官方 HTML"——基底 cbeta_golden.css 永远加载，会重复一份；回官方 = **不传 `--theme`**。

### 8.5 DOCX 翻译限制

DOCX 只把 CSS 的 `TRANSLATABLE` 属性翻译成 OOXML：
`font-size / font-weight / color / font-family / text-align / text-indent / line-height / margin(±left/top/bottom)`。
`display:table` 等纯布局 CSS **不翻译**（偈颂走 `DocxRenderer` 自己的 `<w:br/>` 渲染），故改 pdf_docx.css 时排版类规则只对 PDF 生效。

### 8.6 行距 / rend 字体 / 字体集

- **行距**：CSS `line-height` → `<w:spacing w:line="N×240" w:lineRule="auto"/>`（N=倍数，240=单倍），Word/WPS 显示"N倍行距"。**不用** `exact`（会显示"固定值"，语义不符）。
- **rend 字体**：`rend="kaiti/heiti/mingti/fangsong"` 的元素在 DOCX 输出对应 `w:rFonts w:eastAsia`（繁体集：標楷體/黑體/仿宋/新細明體）；pdf_docx.css 备有 `[rend~=kaiti]` 等钩子供 PDF/HTML。font-family 带逗号时只取第一个字体名。
- **`--font-set '组合:语言'`**：`font_sets` 结构为 **{组合名: {标签: [繁体字体, 简体字体]}}**——每个标签一行写两个字体，无需维护两份平行集合：
  - `--font-set default`（= default 组合繁体，可省略不传）
  - `--font-set zh-Hans`（裸值 zh-Hans → default 组合简体，一键）
  - `--font-set default:zh-Hans`、`--font-set mycombo`、`--font-set mycombo:zh-Hant`
  - 例：`--font-set zh-Hans` = 简体方案（书名楷体/正文宋体/偈颂楷体/脚注宋体）
  - 生效面：DOCX 覆盖各标签 `w:rFonts`；PDF 按 `TAG_SELECTOR` 注入逐标签 `font-family` 规则（追加在样式文件后）。
  - 不传时用 pdf_docx.css 写死的（繁体）方案。
  - **配置外置**：`pycbeta/styles/presets.json`（`{font_sets: {...}, pages: {...}}`），直接改文件，或复制后用 `--presets-file my.json` 指定自定义方案/页面。

### 8.7 DOCX 命名段落样式

DOCX 把核心标签转换为**命名段落样式**（styles.xml），段落用 `<w:pStyle w:val="title">` 引用而非内联 pPr：
- 已转换：`title / head / juan / p / verse / footnote / byline / author`
- 收益：Word/WPS 样式面板可见，改一处样式全文档生效（行距/段距/缩进/对齐）；document.xml 更小
- **run 级保持内联**（动态标签合并 + em 上下文字号，字符样式不可行）
- 未转换（保持内联）：`form/dharani/pre/item`、以及带 XML `style="margin-left"` 脏数据的段落
- 注：`head/juan/byline` 段落的 para 标签直接用自己的 tag（此前误用 "p"），已修正
- **DOCX 版面（2026-08-17）**：正文从 `<body>` 直接开始（书前不再有书名/作者段）；teiHeader 信息（版本資訊/書名/作者/經文資訊/版本記錄/原始資料）放**单独尾页**（`w:pageBreakBefore`）

### 8.8 页面方案（presets.json 的 pages）

页面设置已从硬编码改为 `styles/presets.json` 的 `pages` 段（`--page` 选名字，只管几何）：
- `size`: `[宽mm, 高mm]`；`margins`: 上下左右 mm
- `doc_size`: 文档兜底字号(pt)（DOCX docDefaults）
- 西文字体归入 `font_sets[<组合>].latin` 繁简对（DOCX docDefaults ascii/hAnsi），随 `--font-set` 语言切换；页面方案自带 `latin_font` 仍优先（兼容旧配置）。
- 自定义：`--page tiny --presets-file my.json`；DOCX 和 PDF 同源生效。
- docDefaults 的 eastAsia 仍跟主题 `p` 正文字体；列表编号缩进跟随主题 `list` 的 `margin-left`。

|---|---|---|
| `ignore_xml_style` | 忽略 `<p style="margin-left:…">` 脏数据（缩进统一走 CSS）| DOCX/HTML/PDF |
| `ignore_xml_space` | 忽略文本首尾多余空格（含全角 `\u3000`，如目录行首）| DOCX/HTML/PDF |
| `verse_caesura` | 偈颂 `<caesura/>` 分隔符（默认两个全角空格 `　　`）| DOCX |
| `verse_strip_quotes` | 去掉偈颂首尾的「『 』」引号，同时忽略 lg 的 text-indent 悬挂 | DOCX |
| `grayscale` | 全局黑白输出，忽略所有颜色（程序与 CSS 定义的颜色一律不输出；DOCX 去掉全部 `<w:color>`，PDF 追加 `color/border-color #000 !important` 覆盖规则）| DOCX/PDF |
| `page_border` | 每页四周加框（DOCX 用 `w:pgBorders`；PDF 用 pymupdf 逐页画 0.75pt 黑框，距纸边 24pt）| DOCX/PDF |
| `bookmarks` | 按卷加目录书签（默认 `true`）。PDF：pymupdf `set_toc` 加侧栏大纲（卷标题，页号按"卷起于新页、标题为当页首行"定位，去注码比对）；DOCX：`<w:bookmarkStart w:name="卷N">` 包住每卷首段 + `juan` 样式加 `w:outlineLvl`（Word 导航窗格可见卷目录）| DOCX/PDF |
| `split_juan` | 按卷输出多个文档（默认 `false`）。每卷一个独立文件（书名页+本卷正文+teiHeader 尾页），文件名带 `_卷N`；卷边界用 `<milestone unit="juan"/>`（`split_juans`）切分 | DOCX/PDF |

要点：
- 默认 `false`（忠实复现官方）；内置 `styles/presets.json` 或 `--presets-file` 改 `true`。
- **lg 偈颂悬挂缩进是特征、非脏数据**：`<lg style="margin-left:1em;text-indent:-1em">` 表示首句「引号悬挂对齐，**豁免 ignore_xml_style**，渲染器专门处理（HTML 首格 text-indent；DOCX `w:ind left + firstLine 负值`）。
- **DOCX 偈颂换行**：`<w:br/>` 必须包进 `<w:r>`（裸 `<w:br/>` 是非法 OOXML，WPS 忽略 → 整个 lg 变一行），每 `<l>` 一行、整个 lg 一个段落。

### 8.10 品名/卷名/大纲（2026-08-25）

- **品名双轨**：品名在数据里有两种标记——`<cb:jhead type="pin">`（卷内）与 `<head>`（正文内，如 無常品第三）。DOCX 渲染器按文本特征「…品第X」识别 head 型品名，统一走 `pin` 样式（居中 + 段前段后 + outlineLvl 1 二级目录）。
- **HTML 同步**：`<cb:jhead type="pin">` 也渲染为 `<p data-head-level=N class=head>`（原先是内联无样式）；golden 用书 X1116/YP0012 无 jhead-pin，字节比对不受影响。
- **品名/卷名里的书名冗余**：`<title>大乘入楞伽經</title>` 与书名相同时过滤不输出（品名只剩「現證品第四」、卷名只剩「卷第二」）。
- **卷换页**：每卷从新一页（juan 段落加 `w:pageBreakBefore`），正文第一段（单卷无前文）除外。
- **标题校勘注码**：默认保留；`output.suppress_title_notes=true` 时压制（大纲与正文同时干净——Word 导航取段落全文，无法只清大纲）。

### 9.2 发现的重复与重叠

**D1. 五渲染器的脚手架重复（结构性，可接受）**
`_render_node/_render_children/_render_noteref/_pick_note/_resolve_gaiji/_iter_all` 在 docx/html/md/pdf 中各有一份。html→pdf 有继承关系，docx 与 md 是平行实现。
影响：修 bug 需多处同步（本次「品名居中」「注释开关」均需改 3~4 处）。
建议：中期可抽 `BaseRenderer`（note/gaiji/juan 公共层），短期不动。

**D2. 配置项重叠（config.json 内部）——已去重（2026-08-25）**
- ~~顶层 monochrome~~ 已删除（黑白统一走 output.grayscale）；
- ~~html.pageSize/landscape/margins~~ 已删除（页面尺寸与边距统一走 pages 段）；html 段仅保留渲染特有项（zoom/noteAnchor/linkStyle）；
- engines.pdf / CLI --engine / 环境变量 CBETA_PDF_ENGINE 三级覆盖保留：CLI > env > config（语义明确）。

**D3. CLI 纯透传参数（13 个）**
output 的 13 个选项全部由 CLI 从 presets 读入再透传给渲染器，CLI 本身没有对应开关。
现状可用（改 config.json 生效），但若要命令行临时覆盖需逐个加参数。
建议：保持 config 为权威来源即可；不为它们加 CLI 开关。

**D4. 卷切分逻辑双份**
`render_html.split_juans`（事件流）被 docx/pdf 复用 ✓；但 render_docx 另有 `_render_split`（19 行，按卷出多文件）与 `_render_ops`，与 html 的 `_render_ops` 平行。
建议：可接受（docx 的 div 栈处理不同）。

**D5. 书名==卷名比较用 `_render_text`**
现取 juan 全部后代文本；若 jhead 含 title/mulu 之外内容会比较失真。低风险。

### 9.3 结论

- 无致命重复；主要债务是 D1（五渲染器脚手架）与 D2（配置双写）。
- 短期：仅维护，不加新渲染路径；改样式优先动 css/config，不改代码。
- 中期：若再加格式，先抽公共基类再做。
