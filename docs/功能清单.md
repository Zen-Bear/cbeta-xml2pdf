## 2. 输出格式

### 2.1 HTML（官方格式，render_html.py）
- 分卷输出（每卷一个文件，`_split_juans` 按 milestone 切分）
- 官方 golden 格式逐字节一致（html_epub_official.css 基底）
- 尾注区（#back，校勘 [An] 标记 + noteAnchor 链接）
- 行号 span.lineInfo、缺字 span.gaiji（cbetarc 字体）
- 版权块 #cbeta-copyright
- 主题覆盖：`--pdf-docx-theme`（整套替换）/`--pdf-docx-user-theme`（增量追加）；jhead-pin 品名统一为 head 段落

### 2.2 DOCX（render_docx.py）
见 §3。

### 2.3 PDF —— 共 **4 条转换路径**

| 路径 | 管线 | 引擎/后端 | 说明 |
|---|---|---|---|
| P1 chromium | IR → HTML → PDF | headless Chromium | 默认；横排+竖排 |
| P2 prince | IR → HTML → PDF | PrinceXML | 原生页底脚注(float:footnote)、奇偶页 |
| P3 weasyprint | IR → HTML → PDF | WeasyPrint | Windows 需 GTK/Pango |
| P4 docx2pdf | IR → **DOCX** → PDF | 后端链按序尝试：MS Word(COM) → WPS(COM) → LibreOffice(soffice)；可另接外部引擎 minipdf/docbuilder（config.json engines.external/paths 注册，未安装自动跳过）| PDF 与 DOCX 观感完全一致 |

引擎选择优先级：`--engine` > 环境变量 `CBETA_PDF_ENGINE` > config.json `engines.pdf`。

### 2.4 EPUB3（render_epub.py）
- OPF/nav/NCX 打包；章节由官方格式 HTML 生成；样式随主题

### 2.5 Markdown（render_md.py)
- 标题层级/偈颂缩进/脚注 `[^N]`

## 3. DOCX 渲染功能明细

### 版面与结构
| 功能 | 配置/参数 |
|---|---|
| 命名段落样式 | title/head/juan/pin/p/verse/footnote/byline/author/translator（Word 样式面板可改，全文档生效）|

| 转写行颜色 | `<cb:tt>` 的 `sa-x-rj` 行按主题 `transliteration` 标签着色（默认朱砂，CSS 编辑器「转写」行可调；docx/html 生效）|
| 梵呗注音括号 | `<cb:sg>` 内容半角括号（如 `(音𫬠)`），四格式统一（官方三端一致）|
| 逐字咒文表转写 | `output.show_dharani_transliteration`（默认 false）：txt/md 对逐字咒文表（`<cb:tt>` 无 `place="inline"`）不显示梵文罗马字母（官方 txt 一致）；`place="inline"` 与散文读音不受影响；docx/html 不受影响 |
| 卷换页 | 每卷从新一页；正文第一段除外 |
| 智能分页 pagination | `enabled/duplex/juan/juan_first/mulu_level1/pb/tei`：卷首（第2卷起）、`<cb:mulu level="1">`（序/品/其他）、`<cb:pb>`、尾页均可配置分页；`duplex=true` 每个分页单元置于**单数页**（oddPage 分节，双面打印自动补空白偶页）；`juan_first=true` 书名独占一页（默认 false 紧跟书名）；首个序/品紧跟书名题署块时不切（docNumber/title/byline/juan 卷头不计为可见内容，与 juan_first 无关）；卷头 juan（fun=open）恒为断点，卷头开启新节 |

| 输出文件名 | 默认 `{佛典編號 书名}.{ext}`（与下载电子书 work 目录同款，书名跟随 `source.title_t2s` 转简；`--name-template` 显式覆盖；html 为 `{…}_html/`） |

| PDF 整页缩放 pdf_zoom | 仅 chromium：HTML→PDF 整页等比缩放，不重排（0.1-2.0，如 0.95 收边）；与 font_scale 正交可叠加 |

| 简体转换 t2s | OpenCC t2s 文本层后处理（块级拼接，正文/注释/元数据；`--t2s`，未指定 `--font-lang` 时自动用简体字库；校验时官方文档同步转简体后比对）|
| 目录书签 bookmarks | 每卷 `<bookmarkStart w:name="卷N">` + juan outlineLvl=0；品名 pin outlineLvl=1（二级大纲）|

### 已知限制：PDF 全角空格（U+3000）拷贝断行（2026-10-05，不改）

源 XML 标题常用全角空格分隔（如 `<head>緒　言</head>`、`第一章　釋尊略史`；TX01n0001 的 499 个 head 有 462 个含 U+3000）。WPS/Word 系（docx2pdf 管线）导出 PDF 时，U+3000 被编码为**纯定位间隙、不带空格字形**（PyMuPDF 原始字典实证：`緒` 与 `言` 同基线、间距 1em、无空格字符），PDF 文本提取器按横向间隙判行 → 拷贝/检索得到两行（`緒\n言`）。

- **显示正常**；DOCX/HTML/EPUB/TXT 的拷贝也正常（U+3000 是真实字符）。仅 **PDF 的拷贝/检索**受影响。
- 逐字校验不受影响（`verify.normalize` 折叠 `[\s\u3000]+`）。
- **决定不改**：保持与官方版式一致（官方 HTML 同样保留 U+3000）。若要 PDF 拷贝干净，需把标题内 U+3000 换成半角空格（视觉间隙减半）或删除，本管线不采用。
