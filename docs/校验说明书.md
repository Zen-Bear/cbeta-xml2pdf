# 校验说明书（面向开发 / 测试）

> 校验 = 生成档（本管线 `generate_formal` 产物）vs 官方基线（CBETA 官方 `html/txt/docx/epub` 导出）的**归一后逐字比较**。三入口共用同一校验库 `pycbeta/verify.py`。

---

## 1. 入口与总体流程

```
XML ── P5Parser ── Work(id, title/series/docNumber, body, charDecl)
        │
        ├── generate_formal(fmt, outdir) ── 生成档 ─┐
        │   html→ List[str] 多文件/卷           │
        │   docx/epub/md → 单文件              ├─→ extract_text ─→ strip_docx_head ─→ strip_infos ─→ normalize ─→ diff_stats ─→ missing+extra ≤ maxDiff ?
        │                                      │
        └── find_official(source, stem, kind) ─┘
            官方基线（html/txt/docx/epub 多卷/单卷）
```

三入口：`pycbeta/verify.py:248 verify_one`（GUI 复用）、`test/verify_text.py:17`（`--source E:\dev\cbeta\test`）、`pycbeta/cli.py:332 --verify`（生成后自动校验）。三者参数与分支已对齐。

## 7. P3 辅轨（IR→TXT vs 官方 XML→TXT）

主轨是"我的成品 vs 官方成品"，盲区是 IR 自比对（两侧都经 `P5Parser`，`lb/ed`、`charDecl`、`wit` 等解析层丢字可能错得一致）。辅轨查解析层，不查渲染层。

* 生成侧：`TxtRenderer`（`pycbeta/render_txt.py`，正式第六格式）→ `Work` 线性化裸文本（题署去标记、注文末集中无 `[^n]`、表 TAB 化）。
* 官方侧：`_extract_xml_parts`（`pycbeta/verify.py`）对**输入 XML 本身** lxml 直抽（异构，不走 parser）：只走 `text/body`，`back` 作注池；`anchor` 文档序（`nkr_note_` 去重 + `beg` 位 app-corresp）；注按 `n=` 分组、`mod>orig>add>equivalent>rest` 单选（与 `_pick_note` 同序）；`app/anchor/mulu` 整棵丢、`unclear`→`□`、`<g>` 经 `GaijiDb+charDecl`（与 `_resolve_gaiji_raw` 同优先级）；行内注括号口径与 `generate_formal` 的 `inline_brackets` 同源；版头 `title/author` 与 `_parse_header` 同规则。
* 入口：`test/verify_text.py -f txt --baseline xml`（仅 txt，其余组合报错；报告 `report_xml.txt`）或 `verify_one(..., baseline="xml")`。判据与主轨同一（`normalize` + `diff_stats`，`≤maxDiff`）。
* 现状：`T15n0625`/`X60n1116`/`T12n0349` 0/0（含 t2s）。已知局限：与 parser 共享缺字数据（`GaijiDb`）与版头选取语义，盲区仅限缺字解析本身；主轨 `txt-vs-官方txt` 与 `md` 同类红（官方 txt 行内化全部注变体 + 版头 boilerplate，语义差异非丢字，不在门禁内）。
