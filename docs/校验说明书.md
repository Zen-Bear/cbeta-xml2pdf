# 校验说明书（面向开发 / 测试）

> 校验 = 生成档（本管线 `generate_formal` 产物）vs 官方基线（CBETA 官方 `html/docx/epub` 与 `text-with-notes` 导出）的**归一后逐字比较**。三入口共用同一校验库 `pycbeta/verify.py`。官方 plain `text`（无校注）已弃用，文本族（txt/md）一律对比 `text-with-notes`；epub 首选 `text-with-notes`（官方 epub 含导航/捐款 boilerplate，仅本地现货回退）。各格式 trial 链见配置 `verify.bases`（缺键回退内置）。

> **XML 版本前提**：本管线以发布版 `XML TEI P5`（`cbeta-org/xml-p5`，校勘在 `<back>` + body 锚点）为准。若误用 `P5a/P5b`（CBReader 书库 / 「單卷版」，校勘 body 内联 `<app n><lem><rdg>`），正文 base 读法只在 `<lem>`：渲染器（`render_*.py`）与辅轨 `_extract_xml_parts` 已统一「只取 lem、rdg 不进正文」，但仍会**丢 body `type="add"` 校勘注**且 `<choice>` 未完全对齐，故判为不安全源：`fetch.inspect_xml_source` 抽检 `<edition>`，GUI/CLI 告警。

> **图注**：`<figure><graphic url="…"/>` 在 txt/md 渲染为官方同款 `【圖：<文件名>】`（md 比对官方 txt，口径一致；P3 辅轨同步镜像）；docx/html 无图注文字（官方亦无，用图），保持丢弃。`normalize` 的 `【】` 剥除（≤20 字，去见证标记）对含「圖」的不剥，否则官方图注会被掩盖成缺0。

> **逐字咒文表转写**：官方 `text-with-notes` 对逐字咒文表（`<cb:tt>` 无 `place="inline"`，如 `南無颯哆喃` 的逐字）**不显示**梵文罗马字母，对 `place="inline"` 与散文（如 `此淨法界raṃ`）显示。本管线 txt/md 默认同款（`output.show_dharani_transliteration=false`），P3 辅轨镜像；docx/html 全显示（官方亦全显示）。

> **txt 尾注标记/悉昙占位**：`TxtRenderer` 正文留 `[n]` 标记、文末出 `[n] 内容`（一一对应；`show_notes=false` 全无），官方 text-with-notes 的 `[A**]/[1]` 标记在 `normalize` 中被同样剥除，故不影响比对。无法表示的悉昙字（无 roman）output `◇`(U+25C7)（官方同款），与生成侧 PUA 一起由 `normalize` 归一到 `□`。

> **校验恒比注**：`generate_formal` 一律 `show_notes=True`，**忽略 `output.show_notes`**（转换时取消「显示注释」只影响成品，不影响校验内容）。官方基线含注，若生成档随开关去注会误报大量「缺」。

> **悉昙读音**：官方 docx 正文/脚注均附读音（如 `歾(raṃ)`，取 charDecl `Romanized form in Unicode transcription`）；本管线 `DocxRenderer` 同款输出（读音 run 走 `latin_font`，`output.show_body_siddham=false` 可关正文显示，脚注不受影响）。官方 html 用 `<span class='ranja' roman code char/>` 空元素（CSS 显示，文本为空），本管线同款；官方 txt 用裸读音（`raṃ`），本管线 txt/md/P3 辅轨同款。
> **悉昙文本形（`output.siddham_text`，默认 `false`）**：开则 html/epub/txt/md 有读音悉昙一律按 docx 形输出字形+读音文本（如 `誆(raṃ)`；块级对照表消音与无读音占位规则不变）。**开必挂官方校验**（官方基线各格式本来就不一致：html 空元素、txt 裸读音），阅读版专用；默认关零影响。`<cb:sg>` 四格式统一半角括号（如 `(音𫬠)`）。

### 4.2 注释移动

* `docx` 抽取 `pycbeta/verify.py:46`：`word/document.xml` `</w:p>→\n` + `_TAG_RE` 去标签，`footnotes.xml` 同法后 `"\n"+…` 追加文末。

* `txt` 官方注释已在文末，无需移动。
* `strip_infos` 之前执行，保证校注保留。

### 4.2c cf（confer 参考，不进比对）
`<app><lem>…<note type="cf1">…` 的交叉引用：官方 html/txt 只为 add 型注追加 `(cf. a; b)`，
官方 docx 为全注型追加 ` (cf. a; b)`（前导空格）。`normalize` 统一剥离 `\(cf\.[^)]*\)`，
故各格式/官方差异**不影响缺/多计数**；我方渲染侧按官方口径补齐（docx 全注型、txt/md add 型）。

### 4.2b 图片（不进文本比对）
`<figure><graphic url>` 在六格式中只影响二进制/标签层：html/epub 内嵌 `<img data:…base64>`、
docx 内嵌 `word/media`（`w:drawing`），txt/md 出 `【圖：basename】`；`extract_text` 与
`normalize` 均不保留图片内容，故**图片存在与否不影响缺/多计数**。
图片由 `fetch.ensure_figures` 在材料化/`ensure_baselines` 时预取到 `{work}/figures/`
（`{work}/txt/` 基线 gif 按 basename 复用；缺源按 `downloads.figures` 模板
`https://raw.githubusercontent.com/cbeta-git/CBR2X-figures/master/{canon}/{file}` 下载）；
缺图只警告 + 占位（`【圖：…】`/`<span class='graphic'>`），不中断。纯函数见 `pycbeta/figures.py`。

## 5. 落盘与报告

校验产物按经书独立成 `{输出根}/{id 书名}（验证）/`（内部保持 `{fmt}/` 结构 + `report.txt`；书名跟随 `source.title_t2s`）。GUI：`pycbeta/gui/__main__.py` `BatchWorker._verify_dir` 生成该目录并作为 `verify_one` 的 `out_root`（`{fmt}/` 内为重生成文件 + `*_compare_*.txt`），验证总报告落 `{id 书名}（验证）/{stem}_verify_report.txt`；渲染输出仍在输出根（`out/{id 书名}.{ext}`）。CLI：`--verify` 的 `verify_dir` 由输出根 + `default_output_name` 得出，合并官方文件与 `report.txt` 均在该目录（每经书一份），控制台仍汇总打印。`_compare` 每 `bkind` 一对 `stem_compare_{bkind}_official.txt / {fmt}_generated.txt`，`report.txt` 汇总 `完成时间/源/输出/格式/阈值` 与 `24 compared, 5 failed`（`TX07n0006` 48 卷节选、`YP0019` 节选、`X60n1116` 跨格式 `docx→html` 剩余 `缺199/多224` 为真实正文差异）。

**差异定位（2026-09-13；CLI 对齐 2026-09-28）**：缺/多口径 = `缺=官方有而生成档缺失`（`missing`）/ `多=生成档有而官方没有`（`extra`），注意缺/多是**字符数**（`SequenceMatcher` 字符级），不是行数/处数。报告差异条目改为**精确标记 + 行号定位**：`〖…〗` 标出该 opcode 的实际变更段（变更点前后各 18 字；插入/删除侧显示空括号 `〖〗`）。行号是 `*_compare_*.txt`（TXT 比较文件）的**行号**，非源/生成 DOCX 行号：`【源】/【新】` 路径下各带一行 `【源比较】/【新比较】行号对齐 <cmp 全路径>`；每条差异先单独一行 `N.（源比较第X行，新比较第Y行）`，再列 `【源】/【新】` 片段，最后两行 `【源整行】/【新整行】` 给出 compare 文件整行原文（人工鉴别用；行号不可得时回退提示语）。`〓` 双义：空 span 填充（长度=对侧 span 长）与真实缺字符号并存，存疑去 compare 文件核对该行。`ctx` 条数跟 `--verify-diff-lines` 走（`diff_stats max_ctx`，默认 5；CLI 与 `verify_one` 同）。行映射与落盘 compare 同源（`_display_text` 剥令牌/压缩空行），故行号可直接对应文件。实现：`normalize_with_lines`（逐行归一 + 字符→行号映射；跨行括号等罕见不一致时退回无行号显示）+ `ctx_locations` + `_mark_span` + `cli._frag_lines`。

**反查原文（CLI，2026-09-28）**：每条片段另附两行原始文件定位——`【源文件】基线文件名:行（[n]锚后m行）`（重抽取各基线文件，含正文锚 `[0036004]`/校勘锚 `[A10]`；行号为该文件抽取文本行号）与 `【新文件】正文第N段/脚注M`（docx 按 `document.xml` 段落序号 + `footnotes.xml` 的 `w:id`；其余格式为生成文本行号）。

**顺序校注（2026-09-28，CC0003 实锤）**：比较时注释一律按**阅读顺序**（正文从头到尾遇到注的先后）提取，**双侧同规**。官方 html 尾注按“数字注块 + A 注块”分组（如 X1116、CC0003），而官方 txt/docx 与生成侧均为阅读顺序——故抽取层统一归位：`extract_text` 的 html 分支对注块物理重排（`_reorder_html_footnotes`，仅当注块连续/间隔纯空白时就地重排），`_split_html_text` 对拆分出的注记文本按正文本序重排（`_reorder_footnote_spans`，键口径同 `_join_epub_ours`：正文锚 `note_anchor_{n}`/`cb_note_anchor{seq}`），无锚条目 stable 垫底。**产品文件不动**（html 保持官方分组形态，与官方 html 逐字节 golden 一致；docx/txt/md/epub 本就阅读顺序），`w:id`/锚点/编号不变。覆盖所有比较组合：html 基线（docx→html、html→html、epub→html）双侧遇序化；docx/txt 基线本即遇序。GUI（`verify_one` + `format_verify_report`）同口径：trial 自带 `official_files`，compare 文件直读行，`【源整行】/【新整行】/【源文件】/【新文件】` 与 CLI 一致（查询串取自 compare 整行，由长到短试原样/去标记/最长 CJK 节）。脚注 `w:id` 到 XML 的 `note n=`/`app from-to` 对应：渲染按遭遇序写注，数注序号即得；校勘类注（无 `n=`，如 `又【CB】，及【選集】`）按 `【】` 内见证名 grep XML 的 `wit` 属性。

**epub 注块全局遇序（2026-09-30，X1077 实锤）**：epub 成品 1 卷 html 经 `mulu` 拆多章（spine），背节整体落该卷末章，致**锚点在前面章节、注块在末章**（如 `n0222001 母佛疑倒` 锚在正文早段、块在卷末）。两条抽取路径都按**全局**正文锚点遭遇序归位：**txt trial** 用 `_join_epub_ours`（正文全接 + 注块按全局锚点交错发射；`add` 键按文档序 FIFO 消费，兼容各卷 `cb_note_{seq}` 重号；`note-star` 按位复块；无锚块文档序垫底）；**html/epub trial** 用 `extract_text` 的 epub 分支（`_reorder_epub_footnotes` 逐章把注块按全局锚点位置就地重排，分隔文本原位保留，与官方 html 侧 `_reorder_html_footnotes` 同规）。旧逐文件逻辑只看**本文件**锚点 → 跨章的 `add` 块丢失、`reg` 块垫底，与官方阅读序错位（X1077 epub→txt_notes、epub→html 双修）。单文件输出与旧逻辑逐字节一致；X1077 epub→txt_notes 0/0、epub→html 不再有序差，X1116/X1651/T1859/YP0019 无回归。

**docx 结构护栏（2026-09-28，X1651 实锤）**：文本校验按正则抓 `<w:t>`，无法发现**非法 OOXML 结构**——若渲染出 `<w:p>` 套 `<w:p>`（段中段），Word/WPS 会丢弃嵌套段落，成品丢内容而抽取文字仍在 → 假绿。护栏 `verify.docx_nested_block_violations(path)`（扫描 `word/document.xml`+`word/footnotes.xml` 的 `<w:p>`/`<w:tbl>` 嵌套深度；表格单元格内 `<w:p>` 合法不误报）接在 docx（含 `pdf→docx` 委托产物）生成后；命中即**强制判 fail**（即使文字 0/0），`verify_one` 结果带 `struct_issues`、CLI/报告打 `【结构】段中段 N 处：<定位片段>`。根因侧修复：列表项内嵌块级子改**兄弟段落**渲染（`render_docx._render_item`）。

## 7. P3 辅轨（IR→TXT vs 官方 XML→TXT）

主轨是"我的成品 vs 官方成品"，盲区是 IR 自比对（两侧都经 `P5Parser`，`lb/ed`、`charDecl`、`wit` 等解析层丢字可能错得一致）。辅轨查解析层，不查渲染层。

* 生成侧：`TxtRenderer`（`pycbeta/render_txt.py`，正式第六格式）→ `Work` 线性化裸文本（题署去标记、注文末集中无 `[^n]`、表 TAB 化）。
* 官方侧：`_extract_xml_parts`（`pycbeta/verify.py`）对**输入 XML 本身** lxml 直抽（异构，不走 parser）：只走 `text/body`，`back` 作注池；`anchor` 文档序（`nkr_note_` 去重 + `beg` 位 app-corresp）；注按 `n=` 分组、`mod>orig>add>equivalent>rest` 单选（与 `_pick_note` 同序）；`app/anchor/mulu` 整棵丢、`unclear`→`□`、`<g>` 经 `GaijiDb+charDecl`（与 `_resolve_gaiji_raw` 同优先级）；行内注括号口径与 `generate_formal` 的 `inline_brackets` 同源；版头 `title/author` 与 `_parse_header` 同规则。
