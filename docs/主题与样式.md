# 主题与样式

## 默认样式

| 格式 | 基底 CSS | 来源 | 说明 |
|------|----------|------|------|
| `html` / `epub` | `cbeta_golden.css` | `pycbeta/render_html.py:104 base_css` | 官方电子书样式（在线藏经样式、在线缺字库 `cbetarc`）；CLI 传 `Theme` 时 `pdf_docx.css` 全文再追加覆盖（`render_html.py:199-221`） |
| `pdf` / `docx` | `pdf_docx.css` | `pycbeta/theme.py:17 _DEFAULT_CSS` → `Theme()` | 印刷主题（固定 pt 字号、版心边距、DOCX 命名样式配套）；`Theme` 默认读入 |

`Theme` 的 `tags`（`config.json` 逐标签）会编译为内联 `<style>` 追加在基底之后（`render_html.py:178 theme_css`）。

## 双文件分工与规则级生效范围

先摆管线事实：**PDF 不是手排的**——`IR → PDF-ready HTML+CSS → Chromium 无头打印成 PDF`
（`pycbeta/render_pdf.py:3`）。所以样式层面"HTML/PDF"是同一套（浏览器引擎解释 CSS），
"HTML 和 PDF 格式"即 `-f html` / `-f pdf` 两种输出；DOCX 是另一套（CSS 经 tinycss2 解析成
标签属性表，再翻译成 OOXML，`pycbeta/theme.py:8-9`）。`epub` 内部转调 `HtmlRenderer`
（`render_epub.py:17`），与 `html` 共用基底。

一句话记忆：**`cbeta_golden.css` 管"官方电子书样式"，`pdf_docx.css` 管"像书"**；
调打印效果（docx/pdf）改后者，且只用简单/两段选择器；`[...]` 属性选择器只对网页和 PDF 有效。

`pdf_docx.css` 名义上是 PDF/DOCX 主题，实际四格式都沾：docx（解析翻译）+ pdf（浏览器原样解释）
+ html/epub（golden 之后追加覆盖，冲突时后者赢）。改一条规则前，先看它的选择器形状——
分水岭是 `theme.py:369 _parse_css_tags`：

| 选择器形状 | DOCX | HTML/PDF（含打印出的 PDF） |
|---|---|---|
| 简单选择器（`p.head`、`sup.note-ref`、`div.div-xu`，即 `TAG_SELECTOR` 表里的）+ 可翻译属性（字号/粗体/颜色/字体/对齐/缩进/行距/边距，`TRANSLATABLE`） | ✅ 解析进标签表 | ✅ 原样解释 |
| 两段后代 `A B`（如 `div.div-xu p.head`） | ✅ 进 compounds，祖先栈匹配 | ✅ 浏览器原生 |
| 属性选择器（`p.head[data-head-level="1"]`）、三段及以上、非可翻译声明（如 `display`） | ❌ 忽略 | ✅ 原样解释 |

实战两例（2026-09-06 实锤）：

* 标题分级 `p.head[data-head-level="1..6"]` 只影响 html/pdf；DOCX 下各级 head 一律取 `p.head`
  兜底——改这几行调不了 DOCX 字号。
* 序标题（`<head>` 在 `div-xu` 内）有专属后代规则 `div.div-xu p.head`，四格式通吃；
  要增大序的字号只改这一行的 `font-size`（HTML/PDF 侧其优先级也高于 level 规则，不打架）。

## 多格式同时

`python -m pycbeta -i in.xml -f html,docx` 按 `pycbeta/cli.py:50 render_one` 分发：

* `html` → `HtmlRenderer(theme=None)` → 仅 `cbeta_golden.css`（`1515b`）
* `docx` → `DocxRenderer(theme=None→Theme())` → `pdf_docx.css`（`7296b` 含标签规则）

互不串扰；`--theme custom.css` 则对两者均覆盖。

## 校验正式管线

`pycbeta/verify.py:generate_formal` 与主程序一致 `theme=None` + `load_presets:118`，`html` 仍以 `cbeta_golden.css` 生成，剥样式后正文 `4555` 字一致（`T0349` 实测 `Theme()` vs `None` 字节不等但归一化 `0/0`）。

## 自定义

* `--theme custom.css` 替换主题层（`cli.py:214`）
* `--config custom.json` 替换 `font_sets/pages/output/engines`（`cli.py:263`）
* 校验：`--verify --verify-max-diff 10` 复用同一 `pycbeta/verify.py` 模块，供 `GUI` 调用

## 用户 CSS（`user.css`，可视化编辑器产物）

* 位置：仓库根 `user.css`（`.gitignore`，不入库；删掉即恢复出厂）。
* 内容：自包含完整 CSS（出厂 `pdf_docx.css` 原文 + 编辑器覆盖块），`--theme user.css` 与手写主题等效。
* 生效：GUI 主窗口批量渲染时存在即自动追加 `--theme`；CLI 保持显式（`--theme user.css`）。
* 注意：GUI 默认不传 `--font-set`（default 组合时省略），`Theme` 按"CSS 已指定优先"保留
  `user.css` 字体；显式 `--font-set`/t2s 简体仍会覆盖 CSS 字体（`apply_font_set` 语义不变）。
